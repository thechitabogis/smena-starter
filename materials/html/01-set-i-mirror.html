Сеть и Mirror

Хост на Windows варит один мир. Шлем Quest заходит в него по IP. Mirror — это код сети в Unity, не зеркало шлема и не трансляция картинки.

Ниже восемь вопросов. Под каждым сразу написан ответ.

Что это?

Ответ

Локальная игра — один Play. Окно на ПК видит только этот ПК. Шлем со своим билдом видит только себя, пока нет подключения.

Сетевая игра — несколько программ договорились об одном мире. Картинка у каждого своя. Правда одна.

Сервер решает: кто зашёл, какой объект родился, какое число настоящее.
Клиент рисует и просит.
Хост — сервер и клиент в одном процессе. В классе хост — ПК. Шлем — клиент.
Отдельный сервер без окна и без игрока в классе не нужен: некому нажать Host.

Mirror (в стартере v96.11.2) несёт байты, спавнит объекты и рассылает поля. Транспорт — способ нести байты. У нас KCP, порт 7777. Рядом в той же папке лежат Telepathy (TCP, удобнее ловить ошибку, хуже для частых поз) и SimpleWeb (браузер). На Quest их не включай.

Как работает?

Ответ

Два Play без Host — две отдельные игры, даже если проект один. Один нажал Host, второй вписал IP и Connect — сетевой куб один на двоих. Рисуется он всё равно дважды. Если связь плохая, куб у гостя догоняет рывками, а у хоста окно плавное: хосту пакет «до себя» почти не нужен.

127.0.0.1 — это «я сам». Шлем так до ПК не дойдёт. Нужен IPv4 хоста в той же сети. Его пишет жёлтая строка лобби.

Если у тебя день, а у друга ночь, это не «графика сети». Небо каждый клиент рисует из своей сцены. Сцены разъехались.

  1. На NetworkManager висят транспорт и префаб игрока.
  2. Хост вызывает StartHost(). Клиент пишет адрес в networkAddress и вызывает StartClient().
  3. Сервер в OnServerAddPlayer создаёт игрока и сажает его на соединение. Объект виден всем, только если на префабе есть NetworkIdentity и префаб лежит в Registered Spawnable Prefabs.
  4. Объект, который стоит в сцене с самого старта и должен быть общим, тоже с NetworkIdentity. Его не спавнят вручную.
  5. Дальше три вида сообщений: SyncVar / SyncList — состояние с сервера; Command — просьба клиента серверу; ClientRpc — сервер говорит всем, TargetRpc — одному.

isServer — этот процесс сервер. isClient — клиент. На хосте оба true. isLocalPlayer — это твой игрок. isOwned — у тебя authority на объект (свой аватар или схваченный куб).

Чужой transform ты не двигаешь «по-настоящему». Либо объект твой, либо ты шлёшь Command.

Где взять?

Ответ

  • В стартере Mirror уже лежит: Assets/Mirror. Не ставь его через Package Manager git-URL: у этой папки нет package.json, установка падает.
  • В свой проект копируй ту же папку, чтобы у всего класса была одна версия. Не ставь рядом Photon, Netcode for GameObjects или FishNet. Два сетевых стека в одной сцене не живут.
  • Менеджер на сцене один. В стартере это SmenaNetworkManager. Второй менеджер — вторая игра в том же процессе.

Как настроить?

Ответ

  1. Объект менеджера, KcpTransport, один порт на всех (7777).
  2. Player Prefab с NetworkIdentity. Пустая ссылка даёт в консоли «playerPrefab не назначен».
  3. Don't Destroy On Load, чтобы менеджер пережил смену сцены. В сцене он один.
  4. Пуля, куб, табличка — в список спавна и с NetworkIdentity.
  5. Поза: NetworkTransformUnreliable для рук и куба в руке (часто и с низким лагом, пакет может потеряться). NetworkTransformReliable для двери, которая должна доехать точно. NetworkTransformHybrid есть в этой версии Mirror, но пока хватает одного из первых двух — бери его. На учебном кубе стартера стоит Unreliable. Send Rate 10 на менеджере — это интервал 0,1 с. Буфер = интервал × множитель. В документации советуют около 3, в коде этого релиза по умолчанию 2. Выше множитель — плавнее и с большей задержкой.
  6. Чужой аниматор — NetworkAnimator, не SyncVar на каждый кадр.
  7. Адрес — IPv4 хоста, не localhost.

NetworkManagerHUD — готовые кнопки Host / Client из Mirror. В стартере вместо них свой экран лобби. В своей игре можно начать с HUD, потом заменить кнопки на VR.

Как правильно?

Ответ

  • Правда на сервере. Клиент показывает.
  • Один Host на ПК, остальные — Client на шлеме.
  • Один порт, одна сеть, Wi-Fi без изоляции клиентов.
  • Объект, который видят другие, рождается на сервере.
  • Правило «поднял монету»: Command на сервер, сервер меняет число, SyncVar развозит его всем.

Почему не работает?

Ответ

Что происходитГде искать
Connect крутится, статуса нетIP не хоста, другой порт, разный Wi-Fi, изоляция точки, файрвол на 7777
Хост есть, игрок не появляетсяпустой Player Prefab, нет NetworkIdentity, префаб не в списке спавна
Объект есть только у того, кто нажалInstantiate на клиенте без серверного Spawn

Вы в разных мирахоба нажали Host. Нужен один Host
После смены сцены игрок пропалменеджер не DontDestroyOnLoad, или сцена загружена через SceneManager мимо сервера
В консоли нет типа Mirrorпапку Assets/Mirror не скопировали или она не докомпилировалась

Что ещё можно?

Ответ

  • NetworkDiscovery — шлем сам находит хост, без ввода IP. Сначала всё равно пойми, что такое адрес.
  • Interest management — сервер не шлёт далёкие объекты. Имеет смысл, когда объектов десятки. На пятерых в одной комнате рано.
  • SyncMode: Observers (всем) или Owner (только владельцу). Владельцу — то, что другим рисовать не нужно.
  • Свой транспорт не пиши. Latency Simulation — только чтобы на ПК увидеть лаг, не для билда на Quest.

Как улучшить?

Ответ

  • Реже шли позу лежащего предмета. Руку в захвате — чаще.
  • Не синхронизируй то, что считается на месте: таймер UI, пыль, свой луч.
  • Урон, очки и «я выиграл» считает сервер. Красивый луч можно показать всем через RPC.
  • Один билд — одна версия Mirror. Смешал v96 с другой — подключение может молча не сойтись.
